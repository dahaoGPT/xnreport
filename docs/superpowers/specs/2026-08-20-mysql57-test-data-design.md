# MySQL 5.7 测试数据设计

## 1. 目标

为效能报表生成器提供一套确定、可重复执行且不会误删业务数据的 MySQL 5.7 测试数据。测试数据同时支持当前 6 个数据集 SQL、Excel 可见数据页、趋势图、组合图、饼图、Word 文字分析及嵌套 `AND/OR` 异常规则的人工验证。

## 2. 文件与执行方式

- 新增 `database/mysql57/seed-test-data.sql`。
- 脚本由 MySQL 客户端或 Docker 容器中的 `mysql` 命令直接执行，不由报表的只读 SQL 加载器执行。
- DML 脚本不放入 `config/sql`，避免与只读报表查询混淆。
- 脚本采用 MySQL 5.7 兼容语法和 UTF-8/`utf8mb4` 中文数据。

## 3. 幂等及数据安全

- 测试流程编号、需求编号、人员编号统一使用 `TEST_` 前缀。
- 每次执行时，只删除以下测试数据：
  - `XN_API_DESIGN_FLOW_APPROVAL.PCS_NO LIKE 'TEST\_%'`；
  - `xn_grp.empe_id LIKE 'TEST\_%'`。
- `LIKE` 使用显式转义，确保下划线按普通字符处理。
- 不使用 `TRUNCATE`，不删除表，也不处理没有 `TEST_` 标识的记录。
- 删除和插入放在同一事务中，任一语句失败时由客户端回滚。

## 4. 数据范围

### 4.1 时间范围

- 基准期：2025-01-01 至 2026-01-01，至少为每个测试审批人和中心提供一条有效审批记录。
- 当期：2026-01-01 至 2026-07-01，覆盖 2026 年 1—6 月。
- 所有审批结束时间均大于等于开始时间，避免被现有 SQL 的有效性条件过滤。

### 4.2 组织与人员

- 覆盖开发一中心至开发九中心及研发中心。
- 每个中心至少配置一个测试审批人。
- 人员信息覆盖在岗、离岗、开发组和非开发组，使嵌套 `AND/OR` 规则同时产生命中与不命中结果。
- 节点使用当前报表关注的 API 设计审批节点，并保持 `NOD_NM` 不超过表字段长度。

### 4.3 耗时分布

- 当期数据覆盖不超过 24 小时、24—168 小时和超过 168 小时三个区间。
- 部分人员当期平均耗时高于其 2025 年基准，部分低于或等于基准。
- 月度数据形成明显波动，保证趋势文字能识别当前值、比较值、方向、异常月份和极值月份。
- 中心月度数据同时存在达标与不达标事件，保证堆积柱形加基准折线的组合图有可见系列。

## 5. 数据生成形式

- 使用显式 `INSERT ... VALUES` 记录，便于直接审查每条测试数据。
- 流程编号唯一且含年月、中心、序号信息，便于定位。
- 审批结束时间由固定时间值给出，保证每次导入和查询结果一致。
- `xn_grp` 先插入人员维度，审批事实记录随后插入。

## 6. 验证

脚本结尾提供只读校验查询：

- 测试审批记录总数及基准期/当期数量；
- 10 个中心的记录数量；
- 1 天以内、7 天以内、7 天以上的当期分布；
- 测试人员维度记录数量。

完成导入后，使用当前示例参数执行 6 个报表 SQL，确认：

- 每个数据集均返回数据；
- `duration-distribution.sql` 返回 3 个区间且均有数据；
- `center-monthly.sql` 同时产生达标和不达标事件；
- `person-annual.sql` 能产生高于基准和不高于基准的人员；
- 重复执行种子脚本后，测试记录数保持不变。

## 7. 不在本次范围

- 不修改生产表结构和现有报表 SQL。
- 不向测试数据加入随机值。
- 不清理或改写非 `TEST_` 业务数据。
- 不把数据库账号密码写入 SQL 文件。
