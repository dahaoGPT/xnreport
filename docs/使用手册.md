# xnreport 效能报表生成器使用手册

## 1. 手册适用范围

本手册适用于当前实现：Java 8、Spring Boot 2.7、MySQL 5.7，使用 YAML/JSON 配置文件和 Excel/Word 模板，由 Java 入口类直接调用生成报表。

本版本不提供 REST API。一次执行会：

1. 读取并校验配置；
2. 在同一份只读、可重复读数据快照中执行全部 SQL；
3. 先生成 Excel，再生成 Word；
4. 两个文件都校验成功后一起发布到输出目录。

每条 SQL 对应 Excel 中一个独立且可见的 Sheet。图表引用这些数据 Sheet，打开 Excel 后可通过“图表设计 → 选择数据”查看或调整关联范围。

## 2. 环境准备

### 2.1 软件要求

- JDK 8（不是 JDK 11/17）；
- Maven 3.8 或更高版本；
- MySQL 5.7，推荐 5.7.44；
- Microsoft Excel 和 Word（用于查看和编辑生成结果）；
- 运行集成测试时需要 Docker Desktop 正常运行。

### 2.2 项目目录

```text
config/
  api-design-efficiency.yml       # 报表配置
  sql/*.sql                       # 每个数据集一条只读 SQL
templates/
  api-design-efficiency.xlsx      # Excel 模板
  api-design-efficiency.docx      # Word 模板
output/                           # 最终生成文件
temp/                             # 执行期间的临时工作区
src/main/java/                    # Java 入口和组件代码
```

`output` 和 `temp` 不应提交业务数据；生产环境建议将数据库密码放在环境变量、密钥服务或 Spring Profile 中，不要写入 Git。

## 3. 启动 MySQL 5.7

### 3.1 Docker 启动方式

PowerShell 可执行以下命令（端口 `3307` 可按本机情况修改）：

```powershell
docker pull mysql:5.7.44
docker run -d --name xnreport-mysql57 -p 3307:3306 `
  -e MYSQL_ROOT_PASSWORD=xnreport `
  -e MYSQL_DATABASE=xnreport `
  -e MYSQL_USER=xnreport `
  -e MYSQL_PASSWORD=xnreport `
  mysql:5.7.44 --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
```

等待数据库就绪：

```powershell
docker exec xnreport-mysql57 mysqladmin ping -uroot -pxnreport --silent
```

连接参数示例：

```text
JDBC URL: jdbc:mysql://127.0.0.1:3307/xnreport?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
用户名: xnreport
密码: xnreport
字符集: utf8mb4
```

已有同名容器时无需重复创建：

```powershell
docker start xnreport-mysql57
docker stop xnreport-mysql57
```

### 3.2 建表

在 `xnreport` 数据库中执行以下建表语句。字段别名和报表配置中的 `expectedFields` 不绑定 Java DTO，但 SQL 的输出别名必须保持一致。

```sql
CREATE TABLE IF NOT EXISTS XN_API_DESIGN_FLOW_APPROVAL (
  PCS_NO VARCHAR(32), PCS_NM VARCHAR(200), NOD_NO VARCHAR(32), NOD_NM VARCHAR(10),
  DEMD_NO VARCHAR(32), ITTR_ID VARCHAR(8), ITTR_NM VARCHAR(200),
  ITTR_SYS_NM VARCHAR(200), APRV_PSN_NO VARCHAR(50), APRV_PSN_NM VARCHAR(200),
  CENTR_NM VARCHAR(64), SYS_NM VARCHAR(200), APRV_BGN_TM TIMESTAMP NULL,
  APRV_END_TM TIMESTAMP NULL, APRV_STS VARCHAR(2)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS xn_grp (
  empe_id VARCHAR(50) NOT NULL,
  GRP_CTG VARCHAR(200),
  GRP_LNG VARCHAR(200),
  WTHR_ON_JOB VARCHAR(20),
  PRIMARY KEY (empe_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

业务数据可由现有系统导入。空表也可以执行报表，具体行为由 `policies.emptyData` 决定；示例配置为输出“暂无符合条件的数据”并继续生成文件。

### 4.2 运行参数

示例报表需要以下参数：

| 参数 | 类型 | 用途 |
|---|---|---|
| `startTime` | DATETIME | 本期开始时间，包含 |
| `endTimeExclusive` | DATETIME | 本期结束时间，不包含 |
| `baselineStartTime` | DATETIME | 基准期开始时间 |
| `baselineEndTimeExclusive` | DATETIME | 基准期结束时间，不包含 |
| `centerNames` | STRING_LIST | 中心过滤集合，不能为空 |
| `reportPeriod` | STRING | 封面和文件名，例如 `2026年6月` |
| `preparedDate` | STRING | 封面日期 |

时间条件统一使用左闭右开区间：

```sql
WHERE t.APRV_END_TM >= :startTime
  AND t.APRV_END_TM < :endTimeExclusive
```

半年结束时间应传 `2026-07-01 00:00:00`，不要使用不存在的 `2026-06-31` 或 `24:00:00`。

### 4.3 修改字段的规则

可以直接修改 SQL 的查询字段，不需要创建固定 Java 对象，但以下位置必须同步：

1. SQL 输出列的英文别名；
2. 数据集的 `expectedFields`；
3. Excel `tableBindings.columns`；
4. 图表的 `categoryField` 和系列 `field`；
5. 规则、文字和 Word 表格中引用的字段。

例如：

```sql
DATE_FORMAT(t.APRV_END_TM, '%Y-%m') AS statMonth,
ROUND(AVG(TIMESTAMPDIFF(HOUR, t.APRV_BGN_TM, t.APRV_END_TM)), 2) AS avgHours
```

SQL 必须是单条只读 `SELECT`/CTE，使用命名参数（如 `:startTime`、`:centerNames`），不允许 DDL、DML 或多语句。

### 4.4 AND/OR 和异常描述

异常规则可以嵌套 `AND`、`OR`。例如“平均耗时超过基准，且在岗或属于开发组”：

```yaml
condition:
  operator: AND
  children:
    - operator: GT
      left: {source: CURRENT_FIELD, field: avgHours}
      right: {source: CURRENT_FIELD, field: baselineHours}
    - operator: OR
      children:
        - operator: EQ
          left: {source: CURRENT_FIELD, field: onJob}
          right: {source: LITERAL, value: "1"}
        - operator: CONTAINS
          ignoreCase: true
          left: {source: CURRENT_FIELD, field: groupCategory}
          right: {source: LITERAL, value: "开发"}
```

命中结果可以去重、分组、排序和汇总，并在文字模板中引用：

```text
异常说明：共${rule.abnormalApprovers.matchedCount}人，最高平均耗时${rule.abnormalApprovers.summary.maxHours|number:0.00}小时。
```

## 5. Java 入口调用

### 5.1 直接调用示例

以下代码可放入宿主应用的 `main`、`CommandLineRunner` 或其他批处理入口中。组件不启动 REST 接口。

```java
import com.xn.report.entry.DefaultReportEntry;
import com.xn.report.entry.ExecutionStatus;
import com.xn.report.entry.ReportExecutionRequest;
import com.xn.report.entry.ReportExecutionResult;
import org.springframework.jdbc.datasource.DriverManagerDataSource;

import javax.sql.DataSource;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.time.LocalDateTime;
import java.util.Arrays;
import java.util.LinkedHashMap;
import java.util.Map;

public class GenerateReport {
    public static void main(String[] args) {
        Path root = Paths.get("D:/xnreport").toAbsolutePath();

        DriverManagerDataSource dataSource = new DriverManagerDataSource();
        dataSource.setDriverClassName("com.mysql.cj.jdbc.Driver");
        dataSource.setUrl("jdbc:mysql://127.0.0.1:3307/xnreport"
                + "?useUnicode=true&characterEncoding=utf8"
                + "&serverTimezone=Asia/Shanghai");
        dataSource.setUsername("xnreport");
        dataSource.setPassword("xnreport");

        Map<String, Object> runtime = new LinkedHashMap<String, Object>();
        runtime.put("startTime", LocalDateTime.of(2026, 1, 1, 0, 0));
        runtime.put("endTimeExclusive", LocalDateTime.of(2026, 7, 1, 0, 0));
        runtime.put("baselineStartTime", LocalDateTime.of(2025, 1, 1, 0, 0));
        runtime.put("baselineEndTimeExclusive", LocalDateTime.of(2026, 1, 1, 0, 0));
        runtime.put("centerNames", Arrays.asList("开发一中心", "开发二中心"));
        runtime.put("reportPeriod", "2026年6月");
        runtime.put("preparedDate", "2026年7月23日");

        ReportExecutionRequest request = new ReportExecutionRequest(
                root.resolve("config/api-design-efficiency.yml"),
                root.resolve("config"),
                root.resolve("config/sql"),
                root.resolve("templates"),
                root.resolve("output"),
                root.resolve("temp"),
                runtime);

        ReportExecutionResult result =
                DefaultReportEntry.create((DataSource) dataSource).generate(request);

        System.out.println("status=" + result.getStatus());
        System.out.println("excel=" + result.getExcelPath());
        System.out.println("word=" + result.getWordPath());
        System.out.println("rows=" + result.getDatasetRowCounts());
        if (result.getStatus() == ExecutionStatus.FAILED) {
            throw new IllegalStateException(result.getError() == null
                    ? "report generation failed" : result.getError().toString(),
                    result.getFailure());
        }
    }
}
```

生产环境不要把账号密码写在源码中；将 `DataSource` 改为 Spring Boot 注入的连接池即可：

```java
@Autowired
private DataSource dataSource;

ReportExecutionResult result =
        DefaultReportEntry.create(dataSource).generate(request);
```

### 5.2 执行结果

`ReportExecutionResult` 重点字段：

| 字段 | 说明 |
|---|---|
| `status` | `SUCCESS`、`SUCCESS_WITH_WARNINGS` 或 `FAILED` |
| `excelPath` / `wordPath` | 已发布文件的绝对路径 |
| `datasetRowCounts` | 每个 SQL 实际返回的行数 |
| `warnings` | 按策略处理的空数据、缺失字段或类型转换提示 |
| `failedStage` | 失败发生的阶段 |
| `error` / `failure` | 结构化错误和原始异常 |

只有 `SUCCESS` 或 `SUCCESS_WITH_WARNINGS` 才表示两个文件已经发布。`FAILED` 时不会留下半成品。

## 6. Excel 使用说明

### 6.1 Sheet 和数据

示例配置的 6 条 SQL 会生成 6 个可见 Sheet：

`部门-每月`、`中心-全年`、`中心-每月`、`个人-全年`、`个人-每月`、`时长分布`。

每个 Sheet 包含 SQL 返回的明细/汇总数据和一个 Excel 原生表。数据页不会隐藏，也不会额外生成图表关系页。

### 6.2 查看图表关联

1. 打开生成的 `.xlsx`；
2. 单击图表；
3. 选择“图表设计 → 选择数据”；
4. 在“图例项（系列）”中查看系列名称和数据区域；
5. 在“水平（分类）轴标签”中查看分类字段；
6. 修改 SQL 返回行数或表格数据后，原生图表可以继续在 Excel 中编辑。

组合图在配置中按系列声明类型，例如堆积柱形加基准折线：

```yaml
series:
  - {field: overStandardCount, type: STACKED_COLUMN, stackGroup: events}
  - {field: withinStandardCount, type: STACKED_COLUMN, stackGroup: events}
  - {field: baselineHours, type: LINE, axis: SECONDARY}
```

支持普通柱形、条形、折线、饼图、圆环图、面积图、散点图、气泡图、雷达图、堆积/百分比堆积图及组合图。`STOCK` 需要使用模板已有图表，不能自动降级为其他图表。

## 7. Word 使用说明

Word 模板使用封面占位符和唯一 `{{sections}}` 锚点。章节树由 YAML 的 `word.sections` 动态生成，标题使用 Heading 1–4 和多级编号；不需要手工写“一、”“1.”。

目录配置为：

```yaml
word:
  toc:
    enabled: true
    maxLevel: 4
    updateOnOpen: true
```

打开生成的 Word 后，如目录页码未立即刷新，可按 `Ctrl+A`、`F9` 更新全部域。组件支持场景说明、固定文字、规则文字、图表、表格、单位和附件信息。生成器不会添加水印，模板本身也不应放置水印对象。

## 8. 空数据、缺失字段和类型不匹配

策略可以在报表、数据集、规则或组件级配置，优先级为“组件 > 规则 > 数据集 > 报表 > 系统默认”。

| 场景 | 常用策略 | 建议 |
|---|---|---|
| SQL 返回空数据 | `OUTPUT_MESSAGE`、`SKIP`、`FAIL` | 报表展示通常使用 `OUTPUT_MESSAGE` |
| 字段缺失 | `FAIL`、`USE_DEFAULT`、`WARN_AND_SKIP` | 关键字段使用 `FAIL` |
| 类型不匹配 | `FAIL`、`SAFE_CONVERT`、`WARN_AND_SKIP` | 可安全转换的数字使用 `SAFE_CONVERT` |
| null 值 | `RULE_NOT_MATCHED`、`USE_DEFAULT`、`ALLOW`、`FAIL` | 异常规则通常使用 `RULE_NOT_MATCHED` |
| 未解析占位符 | `FAIL`、`KEEP`、`EMPTY` | 生产报表建议 `FAIL` |

跳过或使用默认值会写入 `warnings`，最终状态为 `SUCCESS_WITH_WARNINGS`。使用 `USE_DEFAULT` 时必须提供非 null 且可转换的默认值。

## 10. 常见问题

### Q1：为什么查询结束时间不能写 `2026-06-31 24:00:00`？

MySQL 不存在 6 月 31 日，`24:00:00` 也不是推荐的 DATETIME 写法。使用下一月第一天的零点，例如 `2026-07-01 00:00:00`，并配合 `< :endTimeExclusive`。

### Q2：修改了 SQL 列名后报字段缺失怎么办？

检查 SQL 别名、`expectedFields`、Excel 表格列、图表系列、规则和文字占位符是否仍使用同一字段名。字段名建议使用稳定的英文别名。

### Q3：为什么 Excel 图表看不到数据关联？

确认图表是 `GENERATED_NATIVE` 或 `TEMPLATE_NATIVE`，并在“图表设计 → 选择数据”中检查系列公式。若使用 `STOCK`，必须在 Excel 模板中预置图表和定位信息。

### Q4：生成失败后 output 目录出现半个文件怎么办？

正常情况下文件会在临时工作区完成并校验后一起发布。若发现残留，检查文件是否被杀毒软件、Excel 或 Word 锁定，并查看 `failedStage`、错误码和原始异常。

### Q5：中文数据乱码怎么办？

数据库、连接串、SQL 文件和模板统一使用 UTF-8。MySQL 5.7 建议使用 `utf8mb4` 字符集和 `utf8mb4_unicode_ci` 排序规则，JDBC URL 增加 `useUnicode=true&characterEncoding=utf8`。

### Q6：如何清理测试数据库？

临时测试容器会自动清理。手动运行的容器可执行：

```powershell
docker stop xnreport-mysql57
docker rm xnreport-mysql57
```

删除容器前请确认其中没有需要保留的业务数据。
