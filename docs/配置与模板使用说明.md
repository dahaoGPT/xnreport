# 配置与模板使用说明

## 1. 运行方式与目录

组件没有 Controller、HTTP 下载接口或定时任务。宿主应用创建 `DatasetQueryService` 后，通过 `DefaultReportEntry.create(queryService).generate(request)` 同步执行。固定阶段为：加载配置、校验、一次性查询全部数据集、分析、生成 Excel、生成 Word、校验文件、原子发布。

`ReportExecutionRequest` 指定配置根目录、SQL 根目录、模板根目录、输出目录和临时目录。所有相对路径都经过根目录边界校验；配置、SQL 和模板不能用 `..` 逃逸。一次执行只使用自己的临时工作区，成功或失败均清理。

推荐目录：

```text
config/<report>.yml            # 也可使用 JSON
config/sql/<dataset>.sql       # UTF-8，只读 SELECT/CTE
templates/<report>.xlsx
templates/<report>.docx
output/                        # 仅最终文件
temp/                          # 每次执行的隔离工作区
```

## 2. YAML/JSON 配置

顶层字段包括：

| 字段 | 说明 |
|---|---|
| `schemaVersion` | 当前示例为 `1.0` |
| `report` | 报表编码、名称、Excel/Word 模板和输出文件名、冲突策略 |
| `parameters` | 运行参数类型、必填、集合长度和默认值 |
| `datasets` | SQL、结果形态、Sheet、字段契约、超时、最大行数和策略 |
| `rules` | 可递归的条件树及去重、排序、分组、汇总结果 |
| `narratives` | 固定模板文字或受控趋势/区间分析文字 |
| `charts` | 图表类型、系列、坐标轴、数据标签和 Excel 锚点 |
| `excel` | 单元格和表格绑定 |
| `word` | 封面、目录、编号、动态章节与组件 |
| `policies` | 报表级异常处理策略 |

组件使用严格反序列化，未知字段会失败。YAML 和 JSON 使用相同模型及 JSON Schema。ID 应稳定且唯一，以便 SQL、规则、文字、图表及 Word 组件互相引用。

### 2.1 运行参数

示例要求 `startTime`、`endTimeExclusive`、`baselineStartTime`、`baselineEndTimeExclusive`、`centerNames`、`reportPeriod` 和 `preparedDate`。日期查询统一使用左闭右开区间：

```sql
WHERE APRV_END_TM >= :startTime
  AND APRV_END_TM < :endTimeExclusive
```

不要使用不存在的日期（例如 6 月 31 日）或 MySQL 5.7 不接受的 `24:00:00`。半年结束值应传下一月第一天 `2026-07-01 00:00:00`，全年结束值应传下一年第一天。

每个数据集的 `parameters` 显式声明 SQL 命名参数来源，例如：

```yaml
parameters:
  centerNames: {from: RUNTIME, key: centerNames}
```

集合参数可以直接用于 `IN (:centerNames)`，空集合默认失败，避免生成含义不明的 SQL。

## 3. SQL 与数据集

MySQL 5.7 示例位于 `config/sql`。`datasets[].sqlFile` 相对于执行请求的 SQL 根目录解析，因此当 `sql-root` 已配置为 `config/sql` 时应写 `center-monthly.sql`，不要重复写成 `sql/center-monthly.sql`。SQL 必须是单条只读查询，不允许 DDL、DML、多语句或注释绕过；配置可设置 `timeoutSeconds` 与 `maxRows`。

所有输出字段必须使用固定英文别名，例如：

```sql
DATE_FORMAT(t.APRV_END_TM, '%Y-%m') AS statMonth,
ROUND(AVG(TIMESTAMPDIFF(HOUR, t.APRV_BGN_TM, t.APRV_END_TM)), 2) AS avgHours
```

别名与 `expectedFields`、规则、文字、表格和图表完全一致。修改查询字段时同步修改这些声明，不需要新增 Java DTO。

一条 SQL 对应一个 `DatasetDefinition`，一个数据集必须配置一个唯一、合法、最长 31 个 UTF-16 单元的 `sheetName`。运行时严格生成一个独立可见 Sheet，不创建隐藏数据页或“图表关系页”。示例的 6 个 SQL 对应 6 个 Sheet。

`resultType` 支持 `SCALAR`、`SINGLE`、`LIST`；`dependsOn` 可声明数据集依赖并进行拓扑排序。查询阶段只执行一次，Excel 和 Word 共用同一份不可变快照。

## 4. 规则与文字

条件树支持 `AND`、`OR`、比较、集合、区间、字符串匹配以及 null 判断。叶子值可来自当前行、其他 `SCALAR/SINGLE` 数据集、运行参数或字面量。示例：

```yaml
condition:
  operator: AND
  children:
    - operator: GT
      left: {source: CURRENT_FIELD, field: avgHours}
      right: {source: CURRENT_FIELD, field: baselineHours}
    - operator: OR
      children: [...]
```

`FIXED_TEMPLATE` 文字可读取 `${runtime.*}`、`${dataset.<id>.<field>}` 和 `${rule.<id>.*}`。例如异常说明读取：

```text
${rule.abnormalApprovers.matchedCount}
${rule.abnormalApprovers.summary.maxHours|number:0.00}
```

`RULE_GENERATED` 文字只允许受控的 `TREND` 或 `DISTRIBUTION` 分析器。趋势可配置比较来源、平稳容差、异常阈值和极值月份；区间可配置开闭边界、数量及占比。格式化器包括 `number`、`percent`、日期时间和集合连接。

## 5. Excel 模板、表格与图表

模板可以预设字体、颜色、列宽和页面设置。数据集写入绑定的 Sheet 与 Excel 原生表（`XSSFTable`），表名在工作簿内唯一且不能形似单元格地址。用户选择图表后打开“选择数据”，能直接看到系列与分类公式引用对应 SQL Sheet。

支持柱形、条形、折线、饼图、圆环图、面积图、散点图、气泡图、雷达图、堆积柱/条/面积图、百分比堆积图和组合图。每个系列可以选择主/次坐标轴、颜色、线型、标记、标签、空值方式和图例顺序。组合图可以混合系列类型；同一堆积组必须使用相容类型和坐标轴。

两种原生图表模式：

- `GENERATED_NATIVE`：程序生成可编辑的 Excel 原生图表；
- `TEMPLATE_NATIVE`：按模板标记或索引更新模板已有图表，保留模板造型。

`STOCK` 仅支持 `TEMPLATE_NATIVE`，不能静默降级为折线或图片。Word 使用同一图表模型渲染 PNG，不改变 Excel 原生图表的可编辑性。

## 6. Word 模板与动态章节

模板必须包含且只包含一组封面占位符：

```text
{{cover:title}}
{{cover:organization}}
{{cover:reportPeriod}}
{{cover:preparedBy}}
{{cover:preparedDate}}
```

封面配置值可包含 `${runtime.reportPeriod}`、`${runtime.preparedDate}` 等运行表达式。解析在每次执行的防御性副本上完成，不修改共享 `ReportDefinition`；缺失值按 `unresolvedPlaceholder` 策略处理，示例配置为 `FAIL`。

模板必须提供 Heading1–Heading4 样式、真实 Word TOC 域和唯一 `{{sections}}` 锚点。`word.toc.updateOnOpen: true` 写入 `w:updateFields`，打开 Word 后更新目录页码和引导线。动态章节最多四层，标题不要手工写“一、”“1.”等编号，程序使用多级编号。

章节组件支持：场景说明、构成要素、固定文字、规则文字、图表、动态表格、单位和附件。组件严格按配置顺序插入。图表可设置宽度、对齐、题注与替代文本；动态表格可指定字段、表头、格式、列宽和空数据文字。

生成器不添加水印。模板本身也不应包含水印对象。输出校验会检查占位符、目录、标题结构、图片、表格及附件信息。

## 7. 策略

策略优先级为“组件 > 规则 > 数据集 > 报表 > 系统默认”。

| 场景 | 主要选项 |
|---|---|
| 空数据 `emptyData` | `FAIL`、`OUTPUT_MESSAGE`、`SKIP`、`USE_DEFAULT`（按适用组件） |
| 字段缺失 `missingField` | `FAIL`、`USE_DEFAULT`、`WARN_AND_SKIP` |
| 类型不匹配 `typeMismatch` | `FAIL`、`SAFE_CONVERT`、`WARN_AND_SKIP` |
| null `nullValue` | `FAIL`、`RULE_NOT_MATCHED`、`USE_DEFAULT`、`ALLOW` |
| 空集合 SQL 参数 | 通常 `FAIL` |
| 未解析占位符 | `FAIL`、`KEEP`、`EMPTY`；生产报表建议 `FAIL` |

使用默认值时必须在字段上配置可安全转换的非 null `defaultValue`。跳过或默认值会形成 `ReportWarning`，成功结果状态为 `SUCCESS_WITH_WARNINGS`。

## 8. 输出与错误码

默认冲突策略为 `VERSIONED`；还可使用实现支持的覆盖/失败策略。Excel 与 Word 先在执行工作区完整生成并验证，再一起发布。Word 生成失败、校验失败、第二个文件发布失败时，不留下半成品；发布完成后的非关键清理异常作为警告返回。

常见错误码：

| 前缀 | 含义 |
|---|---|
| `CFG-001`–`CFG-004` | 配置、引用、路径或 Schema 校验 |
| `SQL-001`–`SQL-004` | SQL 文件、只读防护、参数或执行失败 |
| `DATA-001`–`DATA-004` | 结果形态、缺失字段、类型或最大行数 |
| `RULE-001`–`RULE-002` | 条件或规则执行 |
| `TEXT-001` | 文字/占位符解析 |
| `CHART-001`–`CHART-003` | 图表模型、模式或渲染 |
| `XLSX-001`–`XLSX-002` | Excel 生成或校验 |
| `DOCX-001`–`DOCX-003` | Word 模板、生成或校验 |
| `OUT-001`–`OUT-003` | 输出命名、冲突、发布或回滚 |

排查失败时查看 `ReportExecutionResult.getFailedStage()`、`getError()`、`getFailure()`、数据集行数和警告。原始 cause 会被保留。
